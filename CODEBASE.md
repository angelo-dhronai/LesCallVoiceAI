Executive Summary

  This document describes the current architecture of the Pramukh Group voice calling agent. The agent is named
  Vishal Patel — a warm, consultative real estate sales associate for Pramukh Group. It handles inbound phone calls,
  converses naturally in Hindi, Gujarati, or English, collects lead information, recommends projects, and drives
  callers toward a site visit.

  The system is fully prompt-driven. There is no hardcoded stage machine, no LangGraph, no intent classifier.
  A single OpenAI GPT-4o call handles language detection, conversation flow, objection handling, and data
  collection. Everything that used to be hardcoded — including the opening greeting — is now generated by the LLM.

  LLM Provider: OpenAI only (gpt-4o for conversation, gpt-4o-mini for lead extraction)
  No Anthropic dependency anywhere in the codebase.

  ─────────────────────────────────────────────────────────────────────
  TOP-LEVEL ARCHITECTURE
  ─────────────────────────────────────────────────────────────────────

  End-to-End Call Flow (Production Telephony Path)

  0. FreeSWITCH receives inbound call → answers → dispatches uuid_audio_stream to mod_audio_stream
  0b. mod_audio_stream opens WebSocket to ws_audio_receiver.py (port 9001)
  0c. ws_audio_receiver.py calls conversation_call_bridge.get_or_create() → TelephonySession.start()
  0d. VoicePipeline.start() runs; VoiceAgent.generate_opening() called → LLM generates opening line
  1. Audio Capture: TelephonySource receives PCM frames pushed by ws_audio_receiver.py (PCMU→PCM16, 8k→16k)
  2. Voice Activity Detection: VAD processes frames to detect speech/silence boundaries with calibration
  3. Turn Management: TurnManager accumulates speech and triggers on semantic completion + silence
  4. Speech-to-Text: STTRouter attempts primary (Sarvam saarika:v2.5) then fallback (OpenAI Whisper)
  5. Post-processing: Domain-specific corrections applied to STT output (city names, BHK, phonetic)
  6. Conversation: VoiceAgent.process_stream(text) → OpenAI streaming → sentence-level EngineResult chunks
  7. Text-to-Speech: SarvamTTS streams PCM to TelephonySink → WAV file → FreeSWITCH playback
  8. Lead Extraction: background asyncio.create_task → gpt-4o-mini extracts structured data per turn
  9. Event Broadcasting: EventHub decouples pipeline from WebSocket clients for monitoring

  Production Telephony Bridge

  FreeSWITCH (inbound call)
      ↓ mod_audio_stream WebSocket (port 9001)
  ws_audio_receiver.py  — PCMU→PCM16, 8k→16k normalization; pushes frames to call_bridge
      ↓ conversation_call_bridge.py
  TelephonySession (one per conn_id)
      ↓ TelephonySource.push_frame()   ↑ TelephonySink.wav_queue
  VoicePipeline (voice/pipeline.py)
      → audio_vad_layer → stt_worker → conversation_layer → tts_layer
  TelephonySink.flush() → WAV file → conversation_call_bridge._playback_loop()
      ↓ TCP 127.0.0.1:9004 (length-prefixed JSON playback_request)
  socket_server.py (ESL controller) → bgapi uuid_audio_stream playback → FreeSWITCH

  Key process boundaries: ws_audio_receiver.py and conversation_call_bridge.py share one Python process.
  socket_server.py is a SEPARATE process on TCP port 9004.

  ─────────────────────────────────────────────────────────────────────
  AGENT MODULE — calling-agent/backend/app/agent/
  ─────────────────────────────────────────────────────────────────────

  This is the entire conversation brain. Four files. No external state machine.

  brain.py — VoiceAgent

  - One instance per phone call. Holds ConversationMemory, one AsyncOpenAI client.
  - MODEL: gpt-4o (AGENT_MODEL env var to override)
  - MAX_TOKENS: 300 (AGENT_MAX_TOKENS env var to override)
  - TEMPERATURE: 0.75 (AGENT_TEMPERATURE env var to override)

  generate_opening() → EngineResult
    - Called once when call connects. Sends [CALL_START] trigger to OpenAI.
    - The LLM generates a fresh, natural opener each call — nothing hardcoded.
    - Stores result in memory as first assistant turn (so turn 1 has context).
    - Falls back to "Hello! Pramukh Group, Vishal here. How are you doing?" only on API failure.

  process_stream(user_text) → AsyncIterator[EngineResult]
    - Adds user turn to memory.
    - Builds system prompt from prompts.build_system_prompt(memory).
    - Streams OpenAI response, splits at sentence boundaries (.!?।), yields chunks for TTS.
    - Flushes any trailing text without punctuation after stream ends.
    - On API error: yields language-appropriate fallback (Hindi/Gujarati/English).
    - After full response: calls _background_extract() as asyncio.create_task.

  _background_extract(user_text, agent_text)
    - Calls extractor.extract_lead_update() with gpt-4o-mini.
    - Updates ConversationMemory.lead if new fields extracted.
    - Non-fatal: exceptions are debug-logged only.

  prompts.py — System Prompt

  - build_system_prompt(memory) → str: assembles the full LLM system prompt.
  - PORTFOLIO constant: all 14 Pramukh projects across Surat, Vapi, Silvassa with prices/status.
  - QUICK MATCH GUIDE: budget+city → recommended project mapping.
  - Persona: Vishal Patel, Pramukh Group, 30+ years, 60+ RERA projects.
  - Language rules: Hindi (Devanagari), Gujarati (Gujarati script), English (Roman). No Romanisation.
  - CALL_START rule: on [CALL_START] trigger, generate a warm opener. Vary it each call.
  - Small talk rule: after opener response, acknowledge warmly then transition naturally to discovery.
  - Collection order: city → property type → purpose → budget → timeline. One question at a time.
  - Goals: rapport → needs → specific project recommendation → site visit → name + phone.
  - Lead profile injected from memory.lead.summary_for_prompt() — confirmed fields listed, not re-asked.
  - Firm rules: no emojis, no markdown, no lists, stay in character, 1–3 sentences max.

  memory.py — ConversationMemory + LeadProfile

  LeadProfile (dataclass):
    name, phone, city, property_type, budget, purpose, timeline,
    project_interest, visit_scheduled, visit_datetime

  ConversationMemory:
    - _messages: sliding window of {role, content} dicts, capped at MAX_TURNS*2 = 28 messages.
    - add_user() / add_assistant(): append to _messages, trim if over cap.
    - get_messages(): returns copy for OpenAI messages param.
    - update_lead(updates): only sets a field if currently None/False (no overwriting confirmed data).
    - last_assistant_text(): used for language detection in fallback selection.

  extractor.py — Background Lead Extraction

  extract_lead_update(client, user_text, agent_text, current_lead) → dict
    - Model: gpt-4o-mini (fast, cheap).
    - Sends structured JSON extraction prompt to OpenAI.
    - Returns dict of {field: value} for any fields clearly mentioned in the turn.
    - Only returns updates for fields currently None/False on the lead.
    - Strips markdown fences if model adds them.

  ─────────────────────────────────────────────────────────────────────
  VOICE PIPELINE — calling-agent/backend/app/voice/
  ─────────────────────────────────────────────────────────────────────

  pipeline.py — VoicePipeline

  Four async layers connected by bounded queues:
    audio_vad_layer → stt_queue → stt_worker → transcript_queue
      → conversation_layer → tts_queue → tts_layer

  Queue sizes: audio=40, stt=3, transcript=3, tts=3.
  Audio constants: MIN_SPEECH_MS=300, MAX_SPEECH_SECONDS=4, BARGE_IN_COOLDOWN_MS=400.

  Barge-in: during TTS playback, if VAD energy > barge_in_threshold for BARGE_IN_MIN_FRAMES=3
    consecutive frames AND TTS has played >250ms → stop TTS, flush queues, cancel LLM task.
  Echo cooldown: TTS_ECHO_COOLDOWN_MS=80ms mute after natural TTS completion.

  Conversation layer calls VoiceAgent.generate_opening() once, then process_stream() per turn.
  Streams sentence chunks from process_stream() to tts_queue as they arrive.

  audio_input.py — MicrophoneStream, NoiseGate
  vad.py — VoiceActivityDetector (energy-based, adaptive calibration)
  turn_manager.py — silence + semantic completion gating (600ms silence + word count heuristics)
  event_hub.py — async pub/sub for pipeline events → WebSocket monitors
  stt_stream.py — STT streaming abstraction (unused in telephony path)
  tts_stream.py — StreamingTTS abstract base + MockStreamingTTS
  tts_sarvam.py — SarvamTTS: HTTP stream to Sarvam Bulbul API, PCM16 chunks
  tts_cartesia.py — CartesiaTTS: WebSocket to Cartesia Sonic-2, PCM16 chunks

  stt/ submodule:
    base.py — STTProvider ABC, STTResult, pcm_to_wav()
    sarvam.py — SarvamSTT: primary provider (saarika:v2.5)
    openai_whisper.py — OpenAIWhisperSTT: fallback provider
    router.py — STTRouter: try primary → fallback, confidence filtering, hallucination rejection,
                unsupported script filter, post-processing
    post_processor.py — domain corrections: BHK normalization, city name fixes, Hindi/Gujarati
                        phonetic corrections, real estate term fixes, fuzzy location matching

  ─────────────────────────────────────────────────────────────────────
  PRODUCTION BRIDGE FILES (project root)
  ─────────────────────────────────────────────────────────────────────

  ws_audio_receiver.py
    - WebSocket server on port 9001, receives audio from FreeSWITCH mod_audio_stream.
    - Decodes PCMU → PCM16 (audioop.ulaw2lin), resamples 8k → 16k (audioop.ratecv).
    - Calls conversation_call_bridge.call_bridge.get_or_create() → pushes frames to TelephonySource.

  conversation_call_bridge.py
    - SessionManager.get_or_create(): idempotent TelephonySession per conn_id.
    - TelephonySession.start(): runs pipeline.run_until_shutdown(), playback loop, event loop.
    - Playback loop: reads WAV paths from TelephonySink.wav_queue → sends playback_request to socket_server.
    - Timing observability: first_audio_t, first_transcript_t, first_response_t, first_playback_t.
    - API keys: STT and TTS use SARVAM_API_KEY.
    - TCP 127.0.0.1:9004: 4-byte BE length + JSON playback_request.

  socket_server.py (SEPARATE PROCESS)
    - ESL controller. Listens port 9004 for playback_request from conversation_call_bridge.
    - Injects playback to FreeSWITCH via ESL bgapi uuid_audio_stream.
    - No STT, TTS, LLM, or VAD logic.

  ─────────────────────────────────────────────────────────────────────
  KEY DESIGN DECISIONS
  ─────────────────────────────────────────────────────────────────────

  1. No stage machine. The LLM manages all flow. The system prompt provides persona, language rules,
     conversation order, and the portfolio. The model decides when to ask what.

  2. No hardcoded greeting. generate_opening() uses a [CALL_START] trigger sent to the LLM.
     Every call gets a naturally varied opener.

  3. Lead extraction is decoupled. After each agent turn, gpt-4o-mini runs in the background to
     extract structured fields from the conversation. The main LLM never pauses for this.

  4. Language is fully delegated. Script detection (Gujarati/Devanagari Unicode ranges) is the
     only hardcoding. Everything else — language selection, mixing, switching — is handled by the
     system prompt rules.

  5. STT is still hardened independently. The STT pipeline has its own filtering, post-processing,
     and fallback chain because raw transcripts are unreliable. This is separate from the agent.

  6. Single LLM provider. Only OpenAI. No provider switching logic, no Anthropic SDK.
