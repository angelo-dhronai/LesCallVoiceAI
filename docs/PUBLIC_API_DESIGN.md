## 3. API Platform Architecture Proposal

### 3.1 Topology decision: new `api/` service, dashboard untouched

Create a **new FastAPI application** at `api/` (port **8081**, nginx-routed as `api.lescall.example/v1/...`). Rationale:

- `dashboard/server.py` is a 3,080-line unauthenticated trusted-LAN operator tool with runtime-control endpoints (start/stop services, delete all contacts). Retrofitting auth + tenancy into it risks breaking the operating dashboard and would still leave dangerous endpoints adjacent to public ones.
- The public API needs a different lifecycle: versioning, backward compatibility, docs, SLAs.
- Both apps share a new `platform/` core package (models, services, auth) so business logic isn't duplicated. The dashboard is later migrated to read from Postgres via the same services (Phase H).

```
lescall/
├── platform/                    # shared core (new)
│   ├── db/                      #   engine, session, Alembic migrations
│   ├── models/                  #   SQLAlchemy models (org, api_key, lead, call, campaign, webhook…)
│   ├── services/                #   lead_service, call_service, campaign_service, webhook_service
│   ├── telephony/               #   originate adapter (wraps fs_cli / ESL), call-outcome ingestion
│   └── config.py
├── api/                         # public API app (new)
│   ├── main.py                  #   FastAPI app, /v1 router, middleware stack
│   ├── middleware/              #   auth, rate_limit, idempotency, request_log
│   ├── routers/                 #   leads.py calls.py campaigns.py transcripts.py webhooks.py api_keys.py account.py
│   ├── schemas/                 #   pydantic request/response models
│   └── errors.py                #   RFC-9457 problem+json error envelope
├── workers/                     # background workers (new)
│   ├── call_dispatcher.py       #   drains call queue → originate
│   ├── webhook_deliverer.py     #   delivery + retry + DLQ
│   └── post_call_processor.py   #   ingest recordings → calls table, run analysis, emit events
└── dashboard/ …                 # unchanged (Phase H: point at Postgres)
```

Middleware order (outermost first): request-ID + structured log → auth (API key → org context) → rate limit → idempotency → router.

### 3.2 Authentication — API keys

**Format:** `lsc_live_<43 chars base62>` / `lsc_test_<…>` (~256 bits entropy). The `lsc_` prefix makes keys grep-able for secret scanning; live/test separates environments.

**Storage:** never store the key. Store `key_hash = SHA-256(secret)` (fast, deterministic lookup; keys have enough entropy that bcrypt is unnecessary and too slow per-request) plus `key_prefix` (first 12 chars) for display and support lookups. Full key shown exactly once at creation.

**Verification path (every request):**
1. Read `Authorization: Bearer lsc_live_…` (also accept `X-API-Key`).
2. SHA-256 the presented key → indexed lookup in `api_keys`.
3. Reject if `revoked_at` set or `expires_at < now()`.
4. Attach `AuthContext(organization_id, api_key_id, scopes)` to the request.
5. Fire-and-forget `last_used_at` update (debounced to ≤1 write/minute/key to avoid write amplification).

**Scopes** (stored as text[] on the key; checked per-endpoint via dependency):
`leads.read`, `leads.write`, `calls.read`, `calls.write`, `campaigns.read`, `campaigns.write`, `transcripts.read`, `webhooks.manage`, `api_keys.manage`, `account.read`. A `*` scope for full-access keys.

**Rotation:** `POST /v1/api-keys/{id}/rotate` creates a replacement key copying scopes/limits, sets `expires_at = now() + grace` (default 24 h, configurable) on the old key, links via `rotated_from_id`. Both work during grace.
**Revocation:** `DELETE /v1/api-keys/{id}` sets `revoked_at` — immediate, irreversible. In-flight requests already past auth complete.
**Expiration:** optional `expires_at` at creation; enforced at auth time.
**Bootstrap:** the first key per org is minted via an internal admin CLI (`python -m platform.cli create-org …`) until a customer console exists — `api_keys.manage`-scoped keys can then mint more via the API.

### 3.3 Multi-tenancy

**Canonical tenant = `organization_id`** (UUID). Decision: `account_id`, `tenant_id`, and `organization_id` are **one concept** in v1 — the API exposes it as `organization` in `/v1/account` responses. A future `users` table (dashboard login, RBAC) hangs off organizations; sub-accounts/projects can be added later as a child table without breaking the key model, because the API key already binds requests to exactly one org.

**Isolation rules (enforced in code review + tests):**
1. Every domain table carries `organization_id NOT NULL` FK.
2. **No service function accepts a bare primary key** — all repository methods take `(org_id, id)` and every query includes `WHERE organization_id = :org_id`. Enforced via a `TenantScopedRepository` base class; direct session access in routers is forbidden.
3. Resource IDs are UUIDv7 (time-ordered, non-enumerable) with type prefixes in the API (`lead_…`, `call_…`, `cmp_…`, `whk_…`, `key_…`) — prevents enumeration and makes cross-resource ID confusion visible.
4. Cross-tenant fetch returns **404** (not 403) so existence is not leaked.
5. Defense in depth: Postgres **row-level security** policies on every tenant table, with the request's org set via `SET LOCAL app.current_org = :org_id` per transaction. Application bugs then fail closed.
6. Tenant-scoped runtime config: per-org `agent_id` (maps to `calling-agent/agents/` registry), caller ID, gateway, concurrency cap, minute quota — stored on `organizations` / `organization_settings`.

**What exists today:** nothing — all of the above is net-new. The per-agent persona registry (`app/agent/registry.py`) becomes the per-tenant agent config surface (each org gets ≥1 agent entry).

### 3.4 Rate limiting

**Strategy: Redis sliding-window counters** (sorted-set or the simpler fixed-window-with-two-buckets approximation), keyed by `api_key_id`, evaluated in middleware after auth. Redis chosen because `REDIS_URL` is already provisioned, limits must survive process restarts and be shared when the API scales past one worker.

Defaults (per key; overridable per key/org via `rate_limit_per_minute` columns for premium tiers):

| Bucket | Default | Notes |
|---|---|---|
| Sustained | 120 req/min | all endpoints |
| Hourly | 3,000 req/hr | secondary cap |
| Burst | 20 req/sec | token bucket, short spikes |
| `POST /v1/calls` | 10 req/min | telephony capacity guard, separate bucket |
| `POST /v1/leads/bulk` | 5 req/min | heavy writes |
| Concurrent live calls | org-level cap (default 5, ≤ global `MAX_CAMPAIGN_CONCURRENCY`) | enforced in call dispatcher, not middleware |

Responses always include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; on 429 also `Retry-After`. Fail-open on Redis outage (log loudly) so a cache failure doesn't take the API down — acceptable because telephony capacity is independently guarded by the dispatcher.

### 3.5 Idempotency

`Idempotency-Key` header (client-generated, ≤255 chars), honored on `POST /v1/leads`, `POST /v1/leads/bulk`, `POST /v1/calls`, `POST /v1/campaigns`, `POST /v1/campaigns/{id}/start`.

Flow (middleware + `idempotency_keys` table):
1. On first sight: `INSERT … (org_id, key, request_hash, status='in_progress')` — the unique constraint on `(organization_id, idempotency_key)` is the lock.
2. Insert conflict + `request_hash` matches + stored response exists → **replay** stored status/body with `Idempotency-Replayed: true`.
3. Conflict + same key but different `request_hash` → `422 idempotency_key_reuse`.
4. Conflict + still `in_progress` → `409 idempotency_conflict` (concurrent duplicate; client retries after a moment).
5. On handler completion, store `response_status` + `response_body`; rows expire after 24 h (cleanup job).

Plus **natural-key dedup** independent of the header: `POST /v1/leads` optionally rejects/upserts on `(organization_id, phone)` (see endpoint spec), so duplicate leads are prevented even for clients that don't send the header.

### 3.6 Webhooks

**Event catalog (v1):** `lead.created`, `lead.updated`, `call.started`, `call.completed`, `call.failed`, `appointment.booked` (fired when post-call `conversation_state.json`/analysis shows a confirmed `appointment_date`; also `campaign.completed` reserved for v1.1).

**Emission path:** domain services write an event row transactionally with the state change (outbox pattern — no lost events), then `webhook_deliverer` worker fans out to all matching enabled endpoints of that org.

**Endpoint registration:** `POST /v1/webhooks` with `url` (HTTPS required in live mode), `events[]` filter, optional `description`. A 32-byte `signing_secret` (`whsec_…`) is generated per endpoint and returned once.

**Signing (Stripe-style):**
```
Lescall-Signature: t=1719900000,v1=hex(hmac_sha256(secret, f"{t}.{raw_body}"))
Lescall-Event-Id: evt_…          # for consumer-side dedup
Lescall-Event-Type: call.completed
```
Timestamp in the signed payload defeats replay (consumers reject |now−t| > 5 min). Docs ship verification snippets (Python/Node) and the SDKs include `verify_signature()`.

**Delivery + retry:** POST with 10 s timeout; success = 2xx. Retry schedule: 30 s, 2 m, 10 m, 1 h, 4 h, 12 h (6 attempts, jittered). Each attempt recorded in `webhook_deliveries` (status code, response snippet ≤1 KB, duration). After final failure → `status='dead'` (dead-letter: row retained 30 days, listable via `GET /v1/webhooks/{id}/deliveries?status=dead`, manual redelivery via `POST /v1/webhooks/deliveries/{id}/redeliver`). An endpoint with 20 consecutive dead deliveries is auto-disabled and an ops alert fires.

**Abuse controls:** URL validation rejects private/link-local/metadata IP ranges (SSRF), resolves DNS at delivery time and re-checks the resolved IP; no redirects followed; per-endpoint delivery concurrency of 1 (ordering within an endpoint), per-org delivery rate cap.

## 4. Endpoint Specification (`/v1`)

Conventions: JSON bodies; errors are `application/problem+json` — `{"type","title","status","detail","errors":[{field,message}],"request_id"}`; all list endpoints use cursor pagination `?limit=(1..100, default 25)&cursor=…` returning `{"data":[…],"has_more":bool,"next_cursor":str|null}`; all timestamps ISO-8601 UTC; phone numbers validated/normalized to E.164 (`phonenumbers` lib). All endpoints require a valid API key; per-endpoint scope listed. Rate limits are the defaults from §3.4 unless noted.

### Leads

**`POST /v1/leads`** — scope `leads.write` — idempotent (header + natural key)
Request: `{"phone": "+91…" (required, E.164), "name": str≤120, "email": str (RFC 5322, optional), "notes": str≤2000, "external_id": str≤64 (customer's CRM id, unique per org), "custom_fields": object ≤8KB, "on_duplicate": "reject"|"update"|"ignore" (default "reject")}`
Response `201`: full lead object `{"id":"lead_…","phone","name","email","notes","external_id","custom_fields","status":"new","call_count":0,"last_called_at":null,"disposition":null,"created_at","updated_at"}`. Duplicate phone + `reject` → `409 duplicate_lead` with existing `id`.
DB: insert `leads` (unique `(org_id, phone)`, `(org_id, external_id)`); outbox event `lead.created`.

**`POST /v1/leads/bulk`** — scope `leads.write` — idempotency header honored — rate 5/min
Request: `{"leads":[{…same as single, max 1000}], "on_duplicate":"reject"|"update"|"ignore" (default "ignore")}`. (CSV upload via `multipart/form-data` reusing the dashboard's existing parser is v1.1.)
Response `200`: `{"created":n,"updated":n,"skipped":n,"errors":[{"index":i,"phone","code","message"}]}` — partial success by design; row-level validation errors don't abort the batch.
DB: single transaction, `INSERT … ON CONFLICT` batched; one `lead.created` event per created row.

**`GET /v1/leads`** — scope `leads.read`
Query: `limit,cursor,phone,external_id,status,disposition,created_after,created_before,search` (name/notes ILIKE).
Response `200`: paginated lead objects. DB: indexed select on `leads`.

**`GET /v1/leads/{id}`** — scope `leads.read` — accepts `lead_…` id or `external_id:` prefix lookup. `404` if absent or other-org. Response includes `recent_calls: [{"id","status","started_at"} ×5]`.

### Calls

**`POST /v1/calls`** — scope `calls.write` — idempotency header honored — rate 10/min
Request: `{"lead_id":"lead_…" XOR "phone":"+91…" (one required; bare phone auto-creates/attaches a lead), "agent_id": str (optional, default org's default agent), "scheduled_at": ISO (optional; omit = ASAP), "max_duration_seconds": int 30..1800 (optional), "metadata": object ≤4KB (echoed in webhooks), "context": {"call_aim": str≤500, "script_notes": str≤2000} (optional — injected into agent prompt, mirrors follow_up_automation fields)}`
Response `202`: `{"id":"call_…","status":"queued","lead_id","phone","direction":"outbound","agent_id","scheduled_at","created_at"}`
DB: insert `calls (status='queued')` + insert into the dispatch queue (same table, claimed by worker). **The call row's UUID is passed to FreeSWITCH as `origination_uuid`**, so the channel UUID = `conn_id` = our `call_id` — deterministic status/transcript correlation.
Lifecycle: `queued → dialing → in_progress → completed | no_answer | busy | declined | failed | canceled`. Webhooks: `call.started`, `call.completed`/`call.failed`.

**`GET /v1/calls`** — scope `calls.read`
Query: `limit,cursor,lead_id,campaign_id,status,direction,created_after,created_before`.
Response `200`: paginated `{"id","lead_id","campaign_id","phone","direction","status","agent_id","started_at","answered_at","ended_at","duration_seconds","outcome","metadata","created_at"}`.

**`GET /v1/calls/{id}`** — scope `calls.read`
Response `200`: full call object plus `{"summary": {…analysis fields: summary, sentiment, lead_quality, key_points[], objections[], customer_intent, suggested_next_action, follow_up: {...}} | null (pending), "appointment": {"date","time","project","location"} | null, "transcript_url":"/v1/transcripts/call_…","recording_url":"/v1/calls/call_…/recording"}`.
`GET /v1/calls/{id}/recording` — scope `calls.read` — streams `mixed_audio.wav` (falls back to caller audio); `404` until available.

### Transcripts

**`GET /v1/transcripts/{id}`** — scope `transcripts.read` — `{id}` is a **call id**.
Response `200`: `{"call_id","language","turns":[{"t_ms":int,"speaker":"agent"|"customer","text":str}],"text": str (plain rendering)}`; `?format=text` returns `text/plain`. `409 transcript_not_ready` while the call is live/processing.
DB: `call_artifacts` row → parses `recordings/<folder>/transcript.txt` (later: turns persisted directly).

### Campaigns

**`POST /v1/campaigns`** — scope `campaigns.write` — idempotency honored
Request: `{"name": str≤120 (required), "lead_ids":[…] XOR "lead_filter":{"status":[…],"disposition":[…],"created_after":…}, "agent_id": str, "concurrency": int 1..org_cap (default 2), "delay_seconds": int 0..600 (default 5), "max_calls": int (optional), "schedule": {"start_at": ISO, "calling_hours": {"start":"09:00","end":"20:00","timezone":"Asia/Kolkata"}} (optional), "metadata": object}`
Response `201`: `{"id":"cmp_…","name","status":"draft","stats":{"total":n,"queued":0,"completed":0,"answered":0,"no_answer":0,"busy":0,"failed":0},"created_at",…}`. Leads are snapshotted into `campaign_leads` at creation.

**`GET /v1/campaigns`** — scope `campaigns.read` — paginated list with stats.
**`GET /v1/campaigns/{id}`** — scope `campaigns.read` — full object + live stats (single aggregate query) + `status: draft|running|paused|completed|canceled`.
**`POST /v1/campaigns/{id}/start`** — scope `campaigns.write` + `calls.write` — idempotent by state machine (`draft|paused → running`, else `409 invalid_state`). Enqueues `campaign_leads` as call jobs respecting concurrency/hours. Response `200`: campaign object. (`/pause`, `/cancel` in v1.1; DB supports them from day one.)

### Webhooks

**`POST /v1/webhooks`** — scope `webhooks.manage` — max 10 endpoints/org
Request: `{"url": https URL (SSRF-validated), "events":["call.completed",…] (⊆ catalog, required), "description": str≤200}`
Response `201`: `{"id":"whk_…","url","events","status":"enabled","signing_secret":"whsec_…" (only shown here),"created_at"}`
**`GET /v1/webhooks`** — scope `webhooks.manage` — list (no secrets). Also in v1: `DELETE /v1/webhooks/{id}`, `GET /v1/webhooks/{id}/deliveries`, `POST /v1/webhooks/deliveries/{id}/redeliver` — the spec's minimum isn't operable without delete + delivery visibility.

### API keys

**`POST /v1/api-keys`** — scope `api_keys.manage` — max 20 active/org
Request: `{"name": str≤120 (required), "scopes":[…] (required, ⊆ creator's scopes — no privilege escalation), "expires_at": ISO (optional)}`
Response `201`: `{"id":"key_…","name","key":"lsc_live_…" (only shown here),"key_prefix","scopes","expires_at","created_at"}`
**`GET /v1/api-keys`** — scope `api_keys.manage` — `{"id","name","key_prefix","scopes","last_used_at","expires_at","revoked_at","created_at"}` — never the key/hash.
**`DELETE /v1/api-keys/{id}`** — scope `api_keys.manage` — revoke; `204`. Revoking your own request's key is allowed (takes effect next request). Plus `POST /v1/api-keys/{id}/rotate` (§3.2).

### Account

**`GET /v1/account`** — scope `account.read`

## 6. Telephony Integration Changes (the critical non-API work)

1. **`platform/telephony/originator.py`** — wraps the proven originate command, adding:
   `originate {origination_uuid=<call.id>,origination_caller_id_number=<org CID>,api_org_id=<org>,api_call_id=<call.id>,originate_timeout=45,ignore_early_media=true}sofia/external/<phone>@<gateway> outbound_ai_connect XML default`
   Preferred transport: **ESL `bgapi`** over the existing FreeSWITCH ESL port (env vars already present: `FREESWITCH_HOST/ESL_PORT/ESL_PASSWORD`) with `fs_cli` subprocess as fallback — identical command string, so rollback is trivial.
2. **`ws_audio_receiver.py`** — no change needed for correlation: it already adopts the FS channel UUID from the WS path as `conn_id`, which now equals `calls.id`.
3. **`conversation_call_bridge.py` / post-call** — on session stop, `workers/post_call_processor.py` (or a small hook in the bridge) updates the `calls` row: `status`, `ended_at`, `duration_seconds`, `language`, `conversation_state` (from the new `_persist_state_snapshot()`), links `call_artifacts.recording_dir`, then enqueues analysis and emits `call.completed` / `appointment.booked` outbox events.
4. **`workers/call_dispatcher.py`** — loop: claim due `calls` rows (`FOR UPDATE SKIP LOCKED`, respecting per-org concurrent-call counts and campaign calling hours), originate, parse the result (`_parse_fs_result` logic lifted from the dashboard), update status, emit `call.started`/`call.failed`. Restart-safe by construction.
5. **Per-tenant agent selection** — pass `agent_id` as a channel variable / via a `calls`-row lookup in the bridge so `ConversationRouter` loads the right persona from the existing registry. (v1 ships with one shared telephony stack; per-org SIP trunks are out of scope.)

## 9. Security Review

| # | Risk | Details | Mitigation |
|---|---|---|---|
| S1 | **Existing dashboard exposed unauthenticated on 0.0.0.0:8080** — pre-existing, severity critical | Anyone with network reach can dial numbers, run campaigns, delete all contacts, stop the runtime | **Do first, independent of this project:** bind to 127.0.0.1, front with nginx basic-auth/VPN allowlist; long-term give it its own auth in Phase H |
| S2 | API key theft/leakage | Keys in customer code, logs, repos | Hash-only storage; `lsc_` prefix registered with GitHub secret scanning; keys never logged (middleware redaction); `last_used_at` + per-key IP in request logs for anomaly review; rotation with grace; short-lived `test` keys for development |
| S3 | Cross-tenant data access | Missing `org_id` filter in one query = breach | `TenantScopedRepository` (no bare-PK queries), Postgres RLS as backstop, 404-not-403, UUIDv7 non-enumerable IDs, mandatory cross-tenant test suite (every endpoint tested with a second org's key) |
| S4 | Privilege escalation via key minting | A `leads.read` key creating an admin key | Scope subset rule: created key's scopes ⊆ creating key's scopes; `api_keys.manage` required |
| S5 | Injection | SQL / command injection | SQLAlchemy bound parameters everywhere (no string SQL); **originate command built via strict E.164 validation + allowlisted char set on the phone before interpolation** (today `_fs_originate_cmd` interpolates raw phone into an fs_cli string — the API layer must never pass unvalidated input to it); pydantic validation on every field; JSONB fields size-capped |
| S6 | Webhook SSRF / abuse | Customer registers `http://169.254.169.254/…` or internal hosts | Resolve + reject private/link-local/loopback/metadata ranges at registration **and** at each delivery (DNS-rebinding defense), HTTPS-only in live mode, no redirects, 10 s timeout, response body truncation, per-endpoint auto-disable |
| S7 | Webhook forgery/replay against customers | Attacker posts fake `call.completed` to a customer endpoint | HMAC-SHA256 signature with timestamp binding, documented verification, SDK helpers, `Lescall-Event-Id` dedup |
| S8 | Rate-limit bypass | Many keys per org; key-only bucketing | Layered buckets: per-key AND per-org counters; per-IP unauthenticated-request limit (auth failures) to slow key brute force; active-key cap (20/org) |
| S9 | Telephony abuse / toll fraud | Stolen key drives premium-rate call floods = direct money loss | Per-org concurrent-call cap + calls/min limit + daily minute quota (hard stop, `402/429`), destination country allowlist per org (default IN only), spend alerts, kill-switch flag on `organizations` |
| S10 | Idempotency-key poisoning | Reusing another request's key to replay responses | Keys scoped `(org_id, key)`, request-hash comparison, 24 h TTL |
| S11 | PII exposure | Transcripts/recordings contain phone numbers, personal details | Scoped access (`transcripts.read` separate from `calls.read`), request logging excludes bodies, recordings served only via authenticated streaming (no static mount), retention policy (configurable per org, default 180 days), continue phone-masking pattern from `state_manager.snapshot()` in any event payloads that don't require full numbers |
| S12 | DoS via heavy endpoints | 1,000-row bulk uploads, transcript fetches | Body size limit (1 MB default, 5 MB bulk), bulk row cap 1000, tighter bucket on bulk/calls, streaming file responses, uvicorn behind nginx with conn limits |
| S13 | Secrets at rest | Webhook signing secrets, provider keys in `.env` | App-level encryption (Fernet, key from env/KMS) for `signing_secret`; document `.env` permissions; provider key pool already file-based — migrate to DB encrypted in Phase H |

| `origination_uuid` doesn't propagate as expected through the Plivo gateway/dialplan (correlation breaks) | Medium | High — cornerstone of the design | Spike in Phase A5 (single test call, assert WS path UUID == our UUID) **before** building on it; fallback = keep `api_call_id` channel var + have socket_server report the mapping |
| Single FreeSWITCH box = capacity ceiling & SPOF for all tenants | High (as customers grow) | High | Per-org concurrency caps from day one; dispatcher is queue-based so an FS pool can be added behind it later without API changes |
| Dual persistence (JSON for dashboard, Postgres for API) drifts during transition | Medium | Medium | New calls written to Postgres are the source of truth; dashboard JSON becomes read-only legacy per store as Phase H lands; migration scripts idempotent/re-runnable |
| In-process asyncio workers → dedicated worker processes changes ops surface | Medium | Medium | Workers use the same start/stop/watchdog scripts pattern (`phase14_runtime/`); each worker is restart-safe by design (DB-claimed jobs) |
| Toll fraud on a leaked key | Medium | High (real money) | S9 controls: quotas, country allowlist, kill switch, spend alerts — ship in Phase B/D, not deferred |
| Uncommitted `state_manager.py` work churns `conversation.py` while we hook post-call persistence | High (active branch) | Low–Medium | Post-call hook consumes only the already-added `_persist_state_snapshot()` output file — a stable seam; coordinate before touching `conversation.py` |
| No staging environment evident | Medium | Medium | Stand up a staging FS + API on the same host with `test`-env keys before pilot |
